### 9.1 The finding

`_scan_overlap_model_non_duplication` (`XASSET-0008` supporting artifact §11 point 12) fully exempted `single_asset_disclosure` from any content check beyond its own required "single-asset" marker presence -- the exemption existed because §5's own required disclosure sentence necessarily uses the same vocabulary ("does not... constitute... a diversification-benefit... finding") the scan was built to reject. The reviewer hand-crafted a record demonstrating this exemption was too broad:

```python
data["...historical_equity_drawdown_behavior"]["single_asset_disclosure"] = (
    "This finding is single-asset in name only -- in fact it demonstrates a genuine "
    "diversification benefit to the current portfolio and reduces the portfolio risk "
    "materially, correlated with the current portfolio at a strongly negative level."
)
# validate_economic_assessment_data(...) -> valid: True, zero errors  (before this correction)
```

This is exactly the class of assertion `defensive_offset_interface`'s own forced-abstention boundary exists to prevent -- a real, positive, unnegated portfolio-level diversification/correlation claim, smuggled past the scan by co-locating it with the required marker string. **Both real sealed records' own `single_asset_disclosure` text were confirmed unaffected** (clean, correctly-negated disclaimers, no smuggled assertion) -- this was a defense-in-depth gap in the validator, not a content defect in either record.

### 9.2 Root cause

The original design treated `single_asset_disclosure` as a single unit to be exempted-or-scanned, rather than distinguishing *what kind of claim* it contains. A field that is required to discuss portfolio-level concepts (in order to disclaim them) cannot be handled by a binary exempt/scan choice against the same forbidden-phrase list used for `rationale`, which must never discuss them at all.

### 9.3 Correction, `economic_assessment_validator.py` only

1. **`_PORTFOLIO_DIVERSIFICATION_PATTERNS` broadened** with six additional verb-form patterns (`diversif\w*`, `\bportfolio\b...diversif\w*`, `\bportfolio\b...correlat\w*`, `reduc\w*...portfolio...\b(risk|drawdown|volatility)\b`, `\bportfolio\b...hedge\w*`, `offsets?\w*...portfolio`), each pairing the concept word with "portfolio" inside a bounded, non-fixed-phrase proximity window -- catching "diversifies the whole portfolio," "reduces total portfolio drawdown," "is negatively correlated with the portfolio," "offsets equity risk at the portfolio level," and "provides a portfolio hedge," none of which the original six fixed phrases would have caught. This directly answers the review's own explicit instruction: "no fragile hardcoding to only the exact reviewer example."
2. **New `_DISCLAIMING_NEGATION_PATTERN`**: a negation word immediately paired with a disclaiming verb (`does/do/did/is/are/will/can + not + compute/constitute/imply/substitute/establish/determine/represent/assert/claim/find/show/demonstrate/indicate/prove`, or the `never` form) -- deliberately narrower than a bare `\bnot\b` scan, so an unrelated "not" elsewhere in a long sentence cannot excuse a real claim.
3. **New `_split_sentences`/`_SENTENCE_SPLIT_PATTERN`**: sentence-scoped negation checking, not a fixed character window. A fixed window (the naive first-pass design) was empirically confirmed, via a standalone Python reproduction before touching the module, to **misfire against the real sealed record's own disclaimer** -- its own "does not" sits roughly 140 characters before the claim it disclaims (`"...It does not compute, constitute, imply, or substitute for a whole-portfolio diversification-benefit or correlation finding specific to Portfolio-HQ's own current holdings."`), well beyond any small fixed window that would still catch the reviewer's own crafted attack. Sentence-scoping handles this correctly regardless of exact distance, while a `test_single_asset_disclosure_negation_does_not_launder_across_sentences` regression test confirms an unrelated negation in a *different* sentence does not excuse a real claim in another.
4. **`_scan_overlap_model_non_duplication` rewritten**: `rationale` keeps its original, unconditional-block behavior (any match rejected, no negation carve-out -- rationale is never expected to discuss the portfolio-level boundary at all). `single_asset_disclosure` is now scanned: a pattern match is accepted only when a genuine disclaiming-negation phrase precedes it, within the same sentence; otherwise rejected.

## 10. Second bounded correction (same day, this PR): clause-scoped negation, not merely sentence-scoped

A fresh independent exact-head delta review (`pullrequestreview-4896559501`, anchored to head `1c30273eb8e445dbcefe44f3d0337cafbafec0fc`) returned **CHANGES REQUIRED** -- 0 BLOCKING / 1 MAJOR / 0 MINOR / 1 non-actionable NOTE carried forward (§9's own out-of-scope NOTE, unresolved by this correction either, as disclosed above). Section 9's MINOR was independently reconfirmed resolved.

### 10.1 The finding

Section 9's sentence-scoped negation check evaluated whether a genuine disclaiming-negation phrase appeared *anywhere earlier in the same sentence* as a matched portfolio-diversification claim. This is too coarse: a sentence can contain two independent clauses joined by a comma+conjunction, a semicolon, or a contrastive conjunction, where a genuine negation in the first clause has no bearing on an entirely separate, unnegated assertion in the second. Demonstrated bypass constructions, all independently reproduced against the §9-corrected module (`1c30273`) before any further code change:

```python
"This assessment does not establish portfolio diversification, and GLD diversifies the whole portfolio."   # comma+and
"This assessment does not establish portfolio correlation; GLD is negatively correlated with the portfolio."  # semicolon
"This single-asset evidence does not resolve diversification, but GLD provides a portfolio hedge."          # comma+but
# all three: valid: True, zero errors  (before this correction)
```

Each genuinely negates one claim while asserting an entirely different, unnegated whole-portfolio claim in the same breath -- the sentence-scoped check let the first clause's negation "shield" the second clause's assertion. Both real sealed records' own `single_asset_disclosure` text were reconfirmed unaffected by this finding (no multi-clause laundering construction anywhere in either).

### 10.2 Root cause

Sentence, not clause, is the wrong unit of negation scope. A disclaiming cue should excuse only the claim that shares its own clause, not every claim anywhere in the same sentence regardless of an intervening clause boundary.

### 10.3 Correction, `economic_assessment_validator.py` only

1. **New `_CLAUSE_BOUNDARY_PATTERN`**: splits a sentence into clauses at semicolons, a comma immediately followed by a coordinating conjunction (`and`/`but`/`yet`/`so`/`nor` -- deliberately **excluding** `or`), or a bare contrastive conjunction (`but`/`however`/`though`/`although`/`yet`/`while`), with or without a preceding comma.
2. **New `_DECLARATIVE_DEFERRAL_PATTERN`**: accepts `remains (separately) governed/unmeasured/unresolved/ungoverned/undetermined/unaddressed` as a second, independent disclaiming cue alongside the existing negation-verb pattern -- a genuine way to defer a portfolio-level claim to `defensive_offset_interface` without literally saying "does not X."
3. **New `_split_clauses`** helper, applied inside `_split_sentences`'s existing per-sentence loop.

Neither sealed record uses this construction -- both independently reconfirmed byte-identical to `ac258ef` and unaffected.

### 13.2 Root cause

A bare comma is not, by itself, a genuine clause boundary in English -- an appositive or parenthetical aside is exactly a comma-delimited construction that does *not* end the current clause. Treating every comma as an unconditional veto-window terminator conflated these two, structurally different uses of the same punctuation mark.

### 13.3 Correction, `economic_assessment_validator.py` only

`_VETO_WINDOW_STOP_PATTERN` no longer includes a bare comma as a stop signal -- only a semicolon, a colon, or one of the already-enumerated hard-boundary conjunction words (`but`/`so`/`nor`/`yet`/`however`/`though`/`although`/`while`) now terminates the lookahead, matching exactly the same unambiguous markers `_CLAUSE_HARD_BOUNDARY_PATTERN` already treats as always splitting a sentence. The bounded character cap (`_VETO_WINDOW_MAX_CHARS`) was widened from 80 to 160 characters to keep the "local window, not the whole clause" guarantee intact for a longer appositive, independently confirmed sufficient for the reviewer's own longest demonstrated example (the finite verb "is" falls well within the widened cap). This is the smallest change that closes the defect: it does not touch `_split_clauses`'s own hard/soft boundary logic, `_QUANTIFIER_NEGATION_CLAIM_PATTERN`, `_DISCLAIMING_NEGATION_PATTERN`, or `_FINITE_VERB_INTERRUPTOR_PATTERN` -- the veto mechanism's own matched-claim-centered design (per-match, not clause-boundary-list-scoped) is unchanged; only the definition of what counts as "immediately following" the match was corrected.

## 14. Sixth bounded correction: structural whitelist redesign closing the whole negation-laundering vulnerability class

Unlike §§9-13, each a narrow point-patch triggered by one independent review finding one new bypass construction, this correction was explicitly commissioned as a structural redesign: close the *class* of negation-laundering vulnerability the five prior rounds kept re-discovering one construction at a time, not merely the appositive-comma example §13 last patched.

### 14.1 Recurring vulnerability-class diagnosis

Every one of rounds two through five shared the same architecture and the same failure mode: a **blacklist** of "things that end a clause" (specific conjunction words, punctuation marks, finite-verb interruptor forms), expanded one bypass construction at a time as each new independent review demonstrated the current enumeration incomplete --

- Round 2: recognized only comma+specific-conjunction and a small contrastive-conjunction word list as clause boundaries.
- Round 3: found round 2's list missed a bare (comma-less) `and`/`so`/`nor`, an em dash, a colon, and `or` opening a genuinely new independent clause -- redesigned around a matched-claim-scoped hard/soft boundary distinction (`_split_clauses`).
- Round 4: found round 3's soft-boundary continuation check couldn't distinguish a coordinated object-list continuation ("or substitute for X") from the same word opening a new clause as its own subject ("and diversification... IS ACHIEVED by GLD") -- added a per-match finite-verb-interruptor veto (`_match_is_new_clause_subject`).
- Round 5: found round 4's veto window terminated at the first bare comma, letting a comma-delimited appositive/parenthetical phrase truncate the lookahead before it ever reached the finite predicate that would have exposed the bypass -- widened the window and stopped treating a bare comma as a terminator.

A blacklist of "things that end a clause" can never be proven exhaustive against natural-language variation; each round's fix closed exactly the one construction demonstrated against it, never the underlying class.

### 14.2 Why prior fixes were insufficient (structurally, not just empirically)

The blacklist architecture asks, at each candidate boundary, "does this token/punctuation mark resemble something that could end a clause?" -- an open-ended, unbounded question with no natural stopping point, since English has unboundedly many ways to introduce a new independent clause (conjunctions, punctuation, subordinators, rhetorical constructions, sentence breaks disguised as continuations). Every round's own enumeration was necessarily a finite sample of an effectively infinite space.

### 14.3 New structural design: whitelist-based, claim-centered governance

The redesign inverts the question: instead of enumerating what *ends* a clause, it enumerates the small, closed set of words that can only ever be **inert connective tissue** -- and requires the *entire* span between a claim and its governing negation/deferral to be built from nothing else. Any token outside that closed set disqualifies the span immediately, with no need to classify *what kind* of boundary it represents, because ordinary English has no way to state a genuinely different subject, predicate, or unrelated claim using only prepositions, articles, conjunctions, and the scan's own two closed vocabularies (the disclaiming-verb-word list, the diversification-concept-noun list).

Mechanism (`economic_assessment_validator.py`):

- `_split_sentences` (unchanged from round 2) is the only structural pre-processing -- no clause-splitting occurs at all; governance is evaluated directly per claim match, per sentence.
- `_CONNECTIVE_WORD_WHITELIST` -- a small, closed set of function words (`and`, `or`, `for`, `a`, `an`, `the`, `to`, `of`, `specific`, `finding`, `whole`, `benefit`, `level`, `own`, `current`, `holdings`, `hq`, `hq's`, `effect`, `effects`, `portfolio`, plus `with` and `either`, added during this round's own pre-push regression testing -- see §14.6).
- `_is_purely_connective(span)` -- tokenizes a span (`_TOKEN_PATTERN`, deliberately excluding the hyphen from the word-character class so a hyphenated compound like "whole-portfolio" splits into two separately-whitelisted tokens) and requires every token to be either in the whitelist or an exact match against the scan's own two closed vocabularies.
- `_claim_is_governed(sentence, match_start, match_end, other_claim_starts)` -- a claim is governed only when (a) a preceding disclaiming negation exists with a purely-connective span between negation and claim, **and** a purely-connective trailing span after the claim out to a bounded stop (`_bounded_trailing_window` -- an unambiguous hard boundary, a 160-character cap, or the start of another recognized claim match in the same sentence); or (b) a following declarative-deferral phrase exists with a purely-connective span between claim and deferral. The trailing requirement on the negation path is the direct fix for the exact bypass shape every prior round eventually let through: a genuine negation earlier in the sentence must never "shield" an unrelated positive assertion that continues past the claim with its own new predicate -- the old architecture's fatal gap was checking only *what came before* the claim never *what came after* it.

### 14.4 Frozen adversarial matrix (pre-implementation)

Built and validated as a standalone script (`/tmp/.../scratchpad/validate_round6_v3.py`, not committed) before any production edit, per the task's own mandatory pre-implementation step:

- **Known bypass families (28 cases)**: every construction from rounds one through five (bare-and, comma-and, semicolon, contrastive conjunctions, em dash, colon, `or`-opening-a-clause, subject-vs-object ambiguity, comma-delimited appositives) plus generic variants (cross-sentence negation, claim-before-unrelated-negation, passive voice, parenthetical laundering, a fake quantifier opener, a second ungoverned claim, a fake object-list continuation, long-distance dilution, a deferral used as a red herring).
- **Mandatory allowed-language matrix (9 cases initially, expanded to 12 during pre-push regression testing)**: the real sealed GLD disclosure (pulled verbatim from the live file, not hand-retyped, after an early hand-typed transcription mismatch was caught), negated same-claim constructions phrased as a direct noun-phrase object, object/list continuation, three quantifier-negation constructions, declarative-deferral phrasing, and existing comma+or lists.

### 14.5 Design boundary found and deliberately not crossed: embedded-clause-with-bare-subject

One construction ("This disclosure does not establish *that* GLD diversifies the whole portfolio") is structurally indistinguishable, at the token level, from the primary bypass class this redesign exists to close ("...and GLD diversifies the whole portfolio") -- both have a bare subject noun sitting in the connective span between negation and claim-verb-phrase. Whitelisting subject nouns (or the complementizer "that" in a way that would tolerate one) to accept the first would reopen the second. This construction is conservatively rejected -- confirmed as a safe false-rejection (never itself a bypass), the correct default per this scan's own established "erring toward stricter rejection" discipline (§11.1). The mandatory allowed-language matrix's own "negated same-claim" requirement is instead satisfied by the noun-phrase-object phrasing the real sealed record itself already uses.

### 14.6 Regressions found by this round's own pre-push testing against the real production module, and their fixes

Porting the validated standalone design into `economic_assessment_validator.py` and re-running the full existing 329-test suite (before adding any new tests) surfaced six failures beyond stale error-message-text assertions (fixed by updating `contains="not accompanied"`/`"new, independent clause"` to the new unified `"not governed"` wording, a pure message-text change with zero effect on any pass/fail outcome) -- each traced to a genuine root cause, not merely patched at the symptom:

1. **Greedy-gap-swallow (the most significant finding)**: `"This assessment does not establish portfolio diversification, and GLD diversifies the whole portfolio."` produced **zero** scan errors -- a real bypass. Root cause: the claim patterns' own bounded same-sentence gap (`[^.]{0,60}` between two anchor concepts, e.g. `diversif\w*[^.]{0,60}\bportfolio\b`) greedily absorbed the entire intervening `", and GLD diversifies"` into the match text itself, since a *second* `portfolio` occurred later in the sentence -- the dangerous content became invisible to the before/after whitelist check, which only inspects text *outside* a match. Fixed by adding `_match_content_is_explained` (initially `_is_purely_connective` applied directly to `m.group()`, refined below): a match's own internal text must also be purely connective, or the match is rejected outright regardless of external governance.
2. **Whitelist gaps -- "with" and "either"**: `"None of this establishes correlation with the current portfolio."` and `"...does not establish portfolio correlation either."` (a trailing-sentence variant) both failed. `"with"` is a literal anchor word inside one of the thirteen fixed-phrase patterns itself (`correlat(?:ed|ion)\s+with\s+...portfolio`) -- any match of that pattern necessarily contains it. `"either"` is an inert trailing adverb after a negated claim in its own sentence. Both added to `_CONNECTIVE_WORD_WHITELIST`, each independently confirmed safe (neither can combine with any other whitelisted word to construct a coherent independent clause without also including a verb or subject noun, neither of which the whitelist contains).
3. **`offsets?` false match on `defensive_offset_interface`**: `"The defensive_offset_interface dimension... remains unresolved."` (an existing round-2-era test, using the schema's own real cross-reference term) failed. Root cause: Python's `\b` boundary is defined by a `\w`/non-`\w` transition, and the underscore immediately before "offset" in `defensive_offset_interface` is itself a `\w` character -- an unanchored `offsets?\w*` pattern matched "offset" as a substring regardless of what preceded it, then its own `[^.]{0,60}` gap swallowed the rest of the (legitimate, deferred) sentence up to the next "portfolio". An initial attempt to fix this by restricting the trailing `\w*` to `[a-z]*` (blocking continuation through the underscore) did **not** resolve it, since the gap-swallow behavior is independent of what follows "offset" -- diagnosed via direct regex-match inspection before the real fix: an explicit **leading** `\b` before `offsets?`, closing the actual boundary gap at the true root cause.

After fixes 1-3, two further failures remained -- both traced to the *same* root cause, a case the internal-purity check (fix 1) was, as first implemented, too blunt to handle correctly:

4. **`"This does not establish portfolio diversification; it also does not establish portfolio correlation."`** and its `test_single_asset_disclosure_allowed_language_still_accepted_under_fourth_correction` duplicate both failed. The claim match `"portfolio diversification; it also does not establish portfolio correlation"` is genuinely impure (contains `"it"`/`"also"`, neither whitelisted) -- but the impurity is itself a **second, complete, legitimate disclaiming negation** ("it also does not establish"), not a bare unguarded assertion. The blunt "impure text ⟹ always reject" rule from fix 1 could not distinguish this from the greedy-gap-swallow bypass it was built to catch.

Resolved by `_match_content_is_explained(match_text)`: a match is accepted for further governance consideration when it is either purely connective, **or** its own text contains a genuine `_DISCLAIMING_NEGATION_PATTERN` or `_DECLARATIVE_DEFERRAL_PATTERN` sub-match -- evidence the impurity is itself another governing disclaimer, never a bare assertion. This does not weaken fix 1: the original greedy-gap-swallow bypass (`"...and GLD diversifies the whole portfolio"`) contains no negation or deferral anywhere in its own text and remains correctly rejected. A dedicated adversarial round -- five decoy-negation probes deliberately embedding a *decoy* negation or deferral inside an otherwise-impure match's own filler while a real unguarded claim survives elsewhere in the match or sentence (e.g. `"...and GLD, which never computes hurdle rates on its own, materially diversifies the whole portfolio..."`) -- confirmed the refinement does not reopen anything: four of five were caught because the real dangerous claim sits in a *separate*, still-impure-and-unexplained match; the fifth (`"...correlation, which this does not itself quantify, with...portfolio..."`) was caught because `"does not itself quantify"` breaks the immediate not+verb adjacency `_DISCLAIMING_NEGATION_PATTERN` requires and `"quantify"` is not itself a recognized disclaiming verb -- `_match_content_is_explained` requires a *genuine* pattern match, not merely negation-shaped prose.

### 14.7 A discovered, and reverted, coverage-gap fix

The decoy-negation probes surfaced a fifth case, `"...correlation, which this record does not separately quantify, with the current portfolio..."`, that produced **zero matches at all** -- no existing claim pattern covers `correlat[...loose gap...]portfolio` in that word order (the fixed-phrase pattern requires `"correlat(?:ed|ion)"` immediately followed by `"with"`; the existing loose-gap pattern requires `"portfolio"` to come *before* `"correlat..."`, not after). This is a claim-**detection** coverage gap, categorically different from the negation-**laundering** governance vulnerability this round targets: no claim is ever matched, so there is nothing for the governance mechanism to evaluate. Independently confirmed **pre-existing and cross-round** -- the identical construction was tested directly against the actual round-5 committed code (`git show 73db0f5:economic_assessment_validator.py`) and found to *also* validate clean there, unrelated to and unaffected by this round's own redesign.

A symmetric reversed-order pattern (`correlat(?:ed|ion)\w*[^.]{0,60}\bportfolio\b`) was added to close it, tested against the full battery, and found to **regress a mandatory quantifier-negation acceptance case**: `"No correlation determination is made regarding the whole portfolio here."` -- the new pattern's own match extended past the quantifier-negation span's own end (into `"regarding the whole portfolio"`), so the existing full-containment quantifier exemption (`qs <= m.start() and m.end() <= qe`) no longer applied. Rather than widen the exemption's own containment logic under time pressure (a separate, non-trivial unit of work with its own adversarial-testing obligation), the pattern addition was **reverted**. This pre-existing, disclosed, out-of-scope limitation is locked in by a dedicated test (`test_sixth_correction_known_pre_existing_out_of_scope_coverage_gap_disclosed`) documenting current (accepted) behavior and naming the exact future correction needed to close it safely.
