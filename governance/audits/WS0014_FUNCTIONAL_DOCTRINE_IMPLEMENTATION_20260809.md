## Evidence standard applied (per `XASSET-0006` §C)

Every judgment axis was drafted from `CLAUDE.md`'s own Portfolio Doctrine/Guardrails/Decisions Log text and `targets.yaml`'s symbol/`asset_class` identity rows only — never from `holdings.yaml`'s actual dollar figures, `targets.yaml`'s `target_pct` values, or any `margin_state.py`-computed live account-specific number, per §3.6's contamination rule (independently verified: no such figure appears in any judgment-axis field in any of the four records).

### The two preserved evidence-sufficiency questions (`XASSET-0006` §C), resolved by this implementation

1. **`RESERVE.functional_role` — abstained (`unable_to_determine`).** `CASH`'s own label ("cash") was determined as `operational_liquidity_float` — a near-tautological reading requiring no interpretive leap. `RESERVE`'s own label is genuinely ambiguous among plausible readings (a capital-preservation safety buffer; dry powder held back for future deployment; something else), and no `CLAUDE.md` passage narrates a `RESERVE`-specific purpose beyond the same mechanical allocator fact `CASH` shares ("RESERVE/CASH — never an allocator purchase candidate, definitionally satisfied") — an allocator-behavior fact, not a functional-role narrative. Forcing a value here would be exactly the "force a value merely to fill the record" failure mode `XASSET-0006` §C forecloses. This abstention does not cascade: `RESERVE`'s `liquidity_character` and `capital_preservation_character` axes are both independently determined (`immediately_liquid`, `principal_stable_no_market_risk`) on their own separate evidence.
2. **`DEBT_REDUCTION.freshness_state` — abstained (`unable_to_determine_freshness`).** `holdings.yaml`'s `margin.synced_at` field was considered and explicitly not relied upon: it is a live operational-tracking field, populated by the same `allocate.py update-margin` command that writes the live debt/buffer values themselves, sitting in the same file, with no accompanying governance decision or independent review of its own — structurally different in kind from a standalone governed artifact (an accepted governance decision, or a persisted `classify_margin_state()` run record, neither of which exists for margin state today). Treating it as this record's freshness reference point risked blurring exactly the line §3.6's contamination rule draws between citing that a governed mechanism exists and citing an account-specific live-state field.

For contrast, `CASH`/`RESERVE`'s own `freshness_state` (`stale_needs_refresh`, not abstained) cites `PHQ-2026-06` — a standalone, accepted, independently reviewed governance decision (2026-08-01) recording a governed cash-state sync — a materially stronger evidentiary basis than `margin.synced_at`'s bare live-tracking field, which is the principled, articulable distinction underlying why one axis determines and the other abstains rather than both defaulting to the same treatment.

## Directive-word citation exemption — design note

`XASSET-0005` §7 point 10 names a false-positive risk specific to the word "fund" (a legitimate common noun in real ETF/fund citation text — e.g. GLD's own sealed record cites "SPDR Gold Shares (GLD) fund page"). The exemption implemented here is scoped to exactly three fields: `provenance.sources[].source_identifier`, `provenance.sources[].limitation`, and `hard_constraint_status.constraint_source` — the last one extended beyond the letter of §7 point 10's own ETF/crypto-precedent wording (which named only citation-style fields) because this implementation's own real `DEBT_REDUCTION`/`CASH` records needed to cite `CLAUDE.md`'s own margin-buffer-floor and cash-tight guardrail language, which itself is judgment-free citation text but happens to use ordinary English words. Rather than extend the exemption further, the citation text actually used in `constraint_source` was **paraphrased to avoid the shared eight directive words entirely** (e.g., "purchase" instead of "buy," "forced de-leverage signal" instead of directly quoting `CLAUDE.md`'s own "trim or pay down margin, don't wait it out" clause) — keeping the exemption narrow and the directive-word scan's real-world bite intact. All twelve directive words are individually tested as still-rejected outside the three exempted fields, plus a dedicated test proving the exemption does not swallow a genuine "fund" directive used elsewhere in the document (`later_governance_action`).
